# identitynow_identity_v1 (Data Source)

Reads an Identity from IdentityNow/ISC by `id`, exact `alias`, or exact `email_address`. Exactly one of those arguments must be set. Returns the generated identity fields plus the hand-added `attributes` JSON blob.

## Example Usage

```terraform
# Look up a single identity directly by its ISC identity id.
data "identitynow_identity_v1" "by_id" {
  id = "2c91808576ddc7060176de5040574ab0"
}

# Alternatively, look up the identity by its exact alias.
data "identitynow_identity_v1" "by_alias" {
  alias = "D12345678"
}

# Or look it up by exact email address.
data "identitynow_identity_v1" "by_email" {
  email_address = "last.first@example.com"
}
```

## Schema

### Optional

- `alias` (String) The identity alias to retrieve by exact match when `id` is not set. Exactly one of `id`, `alias`, or `email_address` must be set.
- `email_address` (String) The identity email address to retrieve by exact match when `id` and `alias` are not set. Exactly one of `id`, `alias`, or `email_address` must be set.
- `id` (String) The identity ID to retrieve. Exactly one of `id`, `alias`, or `email_address` must be set.

### Read-Only

- `attributes` (String) Raw identity attributes, represented as a normalized JSON object because the shape is connector-specific and truly dynamic.
- `created` (String) Creation date of the identity
- `identity_status` (String) The identity's status in the system
- `is_manager` (Boolean) Whether this identity is a manager of another identity
- `last_refresh` (String) The last time the identity was refreshed by the system
- `lifecycle_state` (Attributes) Lifecycle state details that include lifecycle state name and whether this lifecycle state has been set manually (see [below for nested schema](#nestedatt--lifecycle_state))
- `manager_ref` (Attributes) Identity's manager (see [below for nested schema](#nestedatt--manager_ref))
- `modified` (String) Last modification date of the identity
- `name` (String) The identity's name is equivalent to its Display Name attribute.
- `processing_state` (String) The processing state of the identity

## Known Limitations & Live Testing Notes

Exactly one of `id`, `alias`, or `email_address` must be set.
`alias`/`email_address` lookups use exact-match server-side filters and return
an error if zero or multiple identities match; use `id` if the alternate key
is not stable or unique enough in your tenant.

`attributes` is intentionally hand-written only on the singular data source as
a normalized JSON string because the API returns a connector-derived dynamic
map that was excluded from Phase 1 codegen.

The reference provider's `use_caller_identity` / `caller_identity_used`
fallback is intentionally **not** implemented here because no clear
"get current caller identity" endpoint was found in the scoped v1 identities
spec. Revisit this only if a concrete practitioner need emerges.
