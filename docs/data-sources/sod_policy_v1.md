# identitynow_sod_policy_v1 (Data Source)

Reads a [Separation of Duties (SOD) Policy](https://documentation.sailpoint.com/saas/help/sod/manage-policies.html) from IdentityNow/ISC by `id`.

~> This is a `_v1` pilot data source - see the "Known Limitations & Live Testing Notes" section below before relying on it in production configurations.

## Example Usage

```terraform
# Look up an existing SOD policy by id. Unlike the `identitynow_segment_v1`
# data source, `identitynow_sod_policy_v1` currently only supports lookup by
# `id` (the sod-policies v1 API has no exact-name-match GET) - see the
# resource docs' Known Limitations for details.
data "identitynow_sod_policy_v1" "example" {
  id = "2c9180835d191305015d28d181fc1234"
}
```

## Known Limitations & Live Testing Notes

See the [`identitynow_sod_policy_v1` resource documentation](../resources/sod_policy_v1.md#known-limitations--live-testing-notes)
for the full list of limitations shared by both the resource and this data
source (both are backed by the same underlying
`conflicting_access_criteria`/`violation_owner_assignment_config`
model/conversion code).

Unlike `identitynow_segment_v1`, this data source only supports lookup by
`id` - the `sod-policies` v1 API has no exact-name-match `GET`, so no
`name` argument is exposed here. Use the plural
[`identitynow_sod_policies_v1` data source](sod_policies_v1.md) with a
server-side `filters` expression (e.g. `name eq "..."`) if you need to
resolve a policy by name.
