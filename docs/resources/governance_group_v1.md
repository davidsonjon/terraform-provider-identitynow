# identitynow_governance_group_v1 (Resource)

Manages a [Governance Group](https://documentation.sailpoint.com/saas/help/common/governance_groups.html) in IdentityNow/ISC.

~> This is a `_v1` pilot resource - see the "Known Limitations & Live Testing Notes" section below before relying on it in production configurations. Membership/connections sub-resources are not yet modeled here - see the package doc.

## Example Usage

```terraform
resource "identitynow_governance_group_v1" "example" {
  name        = "example-governance-group"
  description = "Managed by Terraform."

  owner = {
    id   = "2c91808576ddc7060176de5040574aa0"
    type = "IDENTITY"
  }
}
```

## Known Limitations & Live Testing Notes

This resource is a `_v1` pilot: schema/model types are generated by
`tfplugingen-framework` from SailPoint's per-service `/workgroups/v1`
OpenAPI spec (service folder `governance-groups`), but Create/Read/Update/
Delete are hand-written against the `golang-sdk`'s
`api_beta.GovernanceGroupsAPIService` client.

- **Membership/connection management is out of scope for this resource.**
  The `/workgroups/v1/{workgroupId}/members[/bulk-add|/bulk-delete]` and
  `/workgroups/v1/{workgroupId}/connections` endpoints are separate
  collection-management APIs, not part of the `WorkgroupDto` CRUD lifecycle
  modeled here. `member_count`/`connection_count` are read-only/Computed
  reflections of state managed elsewhere (e.g. the IdentityNow UI, or a
  future dedicated `identitynow_governance_group_members_v1` resource) and
  will drift from configuration if members/connections change outside
  Terraform - this is expected, not a bug.
- **Update only patches `name`, `description`, and `owner`.** Per the API
  spec's own description, these are the only fields `PATCH
  /workgroups/v1/{id}` supports; `member_count`/`connection_count` cannot be
  written and are always sourced from the API response.
- **Live sandbox-tenant verification is still pending for this pilot** as of
  its initial implementation - the schema/type-mapping/build were validated
  offline (`go build`/`vet`/`test`, `golangci-lint`, `tfplugindocs`,
  `terraform validate`), but no `terraform plan`/`apply` has yet been run
  against a real tenant. Treat this resource with the same caution as any
  other freshly-added `_v1` pilot until that follow-up is completed.
