# identitynow_governance_group_v1 (Resource)

Manages a [Governance Group](https://documentation.sailpoint.com/saas/help/common/governance_groups.html) in IdentityNow/ISC.

~> This is a `_v1` pilot resource - see the "Known Limitations & Live Testing Notes" section below before relying on it in production configurations. Membership/connections sub-resources are not yet modeled here - see the package doc.

## Example Usage

```terraform
resource "identitynow_governance_group_v1" "example" {
  name        = "example-governance-group"
  description = "Managed by Terraform."

  owner = {
    id   = "2c91808576ddc7060176de5040574aa0"
    type = "IDENTITY"
  }
}
```

## Known Limitations & Live Testing Notes

This resource's schema/model types are generated by `tfplugingen-framework`
from SailPoint's per-service `/workgroups/v1` OpenAPI spec (service folder
`governance-groups`); Create/Read/Update/Delete are hand-written against
`golang-sdk/v3`'s `governance_groups.GovernanceGroupsAPIService` client.

- **Membership/connection management is handled by separate, dedicated
  targets, not this resource.** The `/workgroups/v1/{workgroupId}/members
  [/bulk-add|/bulk-delete]` and `/workgroups/v1/{workgroupId}/connections`
  endpoints are modeled by the
  [`identitynow_governance_group_members_v1` resource](governance_group_members_v1.md)
  and the
  [`identitynow_governance_group_connections_v1` data source](../data-sources/governance_group_connections_v1.md)
  respectively, not part of the `WorkgroupDto` CRUD lifecycle modeled here.
  `member_count`/`connection_count` are read-only/Computed reflections of
  state managed by those other targets (or e.g. the IdentityNow UI) and
  will drift from this resource's configuration if members/connections
  change outside of it - this is expected, not a bug.
- **Update only patches `name`, `description`, and `owner`.** Per the API
  spec's own description, these are the only fields `PATCH
  /workgroups/v1/{id}` supports; `member_count`/`connection_count` cannot be
  written and are always sourced from the API response.
- **Live sandbox-tenant verification (Phase B) is complete for this
  resource.** A full create/plan(no-drift)/destroy cycle was run against a
  real sandbox tenant, including the discovery (and fix) of a spec-vs-API
  mismatch: the OpenAPI spec marks `owner` as optional, but the live
  `POST /workgroups/v1` endpoint 400s if it's omitted - `owner` is
  therefore enforced as `Required` in this resource's schema regardless of
  what the spec's own `required` array says.
