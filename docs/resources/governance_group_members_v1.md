# identitynow_governance_group_members_v1 (Resource)

Manages the complete set of identity members of a [Governance Group](https://documentation.sailpoint.com/saas/help/common/governance_groups.html) in IdentityNow/ISC, via `POST /workgroups/v1/{workgroupId}/members/bulk-add` and `POST /workgroups/v1/{workgroupId}/members/bulk-delete`.

~> This is a `_v1` pilot resource. Exactly one `identitynow_governance_group_members_v1` resource should be created per governance group - it manages the *entire* membership list, reconciling it to match `member_ids` exactly (including removing any members not listed) on every apply. Only identity members are supported (the underlying API's `type` field only accepts `IDENTITY`).

## Example Usage

```terraform
# Manages the complete membership list of a governance group. Exactly one
# identitynow_governance_group_members_v1 resource should be created per
# governance group - it reconciles actual membership to match member_ids
# exactly on every apply.
resource "identitynow_governance_group_members_v1" "example" {
  governance_group_id = "2c91808a7813090a017814121919ecca"

  member_ids = [
    "2c7180a46faadee4016fb4e018c20642",
    "2c7180a46faadee4016fb4e018c20643",
  ]
}
```

## Schema

### Required

- `governance_group_id` (String) ID of the Governance Group whose membership is managed. Changing this forces replacement.
- `member_ids` (Set of String) Complete set of identity IDs that should be members of the Governance Group. This resource reconciles actual membership to exactly match this set on every apply.

### Read-Only

- `id` (String) Same value as `governance_group_id`.

## Known Limitations & Live Testing Notes

See the [`identitynow_governance_group_v1` resource documentation](governance_group_v1.md#known-limitations--live-testing-notes)
for background shared by all Governance Group targets (SDK client used,
live-testing notes).
Membership management specifically has its own considerations:

- **This resource manages the *entire* membership list, not incremental
  adds/removes.** Every `terraform apply` reconciles actual group membership
  to exactly match `member_ids` - members added out of Terraform (e.g. via
  the IdentityNow UI or another automation) will be removed on the next
  apply.
- **Exactly one `identitynow_governance_group_members_v1` resource should
  exist per governance group.** Creating more than one for the same
  `governance_group_id` results in each apply fighting over the same
  membership list.
- **Only identity members are supported.** The underlying
  `/workgroups/v1/{workgroupId}/members/bulk-add` and `/bulk-delete`
  endpoints' `type` field only accepts `IDENTITY` in the current SDK.
