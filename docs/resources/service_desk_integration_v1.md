# identitynow_service_desk_integration_v1 (Resource)

Manages a [Service Desk Integration](https://documentation.sailpoint.com/saas/help/integration/help/landing-service-desk.html) in IdentityNow/ISC.

~> This is a `_v1` pilot resource - see the "Known Limitations & Live Testing Notes" section below before relying on it in production configurations.

## Example Usage

```terraform
resource "identitynow_service_desk_integration_v1" "example" {
  name        = "example-sdi"
  description = "Managed by Terraform."
  type        = "ServiceNowSDIM"

  # NOTE: the OpenAPI spec only lists name/description/type/attributes as
  # required, but live testing against a real tenant showed the "ServiceNowSDIM"
  # (and "Generic SDIM") connector types actually reject Create without
  # cluster_ref set - include it even though the schema treats it as optional.
  cluster_ref = {
    id = "2c91808576ddc7060176de5040574ac0"
  }

  attributes = {}
}
```

## Known Limitations & Live Testing Notes

This resource's schema/model types are generated by `tfplugingen-framework`
from SailPoint's per-service `/service-desk-integrations/v1` OpenAPI spec,
and Create/Read/Update/Delete are hand-written against `golang-sdk/v3`'s
`service_desk_integration.ServiceDeskIntegrationAPIService` client. The
following was learned from running `terraform apply`, acceptance tests, and
unit tests against real API/SDK behavior, not just from the spec:

- **`cluster_ref` is effectively required for some connector types**,
  despite the OpenAPI spec only listing `name`/`description`/`type`/
  `attributes` as required. Live testing against a real sandbox tenant showed
  `Create` fails outright for the `ServiceNowSDIM` (and `Generic SDIM`)
  connector `type`s when `cluster_ref` is omitted. Always set `cluster_ref`
  unless you have verified your specific connector type does not need it.
- **Previously-known upstream SDK bug for `provisioning_config.managed_resource_refs`
  is now RESOLVED as of the `golang-sdk/v3` migration.** The old
  `golang-sdk/v2`'s `ProvisioningConfigManagedResourceRefsInner.Type/Id/Name`
  fields were mistyped as `map[string]interface{}` instead of `string`
  (confirmed by direct source inspection across multiple v2 releases, never
  fixed by a version bump within v2), which meant the SDK itself could not
  decode a real API response for any service desk integration whose
  `provisioningConfig.managedResourceRefs` was non-empty. `golang-sdk/v3`'s
  equivalent type (`service_desk_integration.ServiceDeskSource`) correctly
  types `Type`/`Id`/`Name` as `*string`, so this no longer occurs. This
  provider still ships the old raw-JSON fallback decode path
  (`sdk_fallback.go`) as harmless defensive/dead code pending a live-tenant
  read of an integration with populated `managedResourceRefs` to fully
  confirm end-to-end before removing it.
- **Optional+Computed nested reference blocks must guard `IsUnknown()`,
  not just `IsNull()`, before Create.** `before_provisioning_rule`,
  `cluster_ref`, and `owner_ref` are `Optional+Computed`, so when omitted
  from configuration Terraform sends them as *Unknown* (not *Null*) to
  `Create` - normal Optional+Computed plan behavior. Only `plan`-only
  validation was run for a long time, which never surfaces this because
  `plan` never invokes `Create`; a real acceptance-test `apply` caught it.
