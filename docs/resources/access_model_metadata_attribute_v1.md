# identitynow_access_model_metadata_attribute_v1 (Resource)

Manages an [Access Model Metadata](https://documentation.sailpoint.com/saas/help/access/metadata.html) Attribute in IdentityNow/ISC - a shared, tenant-wide metadata attribute (with its allowed values) that can be assigned to entitlements, access profiles, and roles to add contextual information (risk, regulations, privacy levels, etc.).

~> This is a `_v1` pilot resource - see "Known Limitations & Live Testing Notes" below. Notably, `Delete` uses a hand-rolled HTTP call rather than the golang-sdk (whose generated client has no delete method for this resource - a spec/SDK documentation gap, not a real API limitation).

## Example Usage

```terraform
# NOTE: this resource's Delete uses a hand-rolled HTTP call, not the
# golang-sdk, because SailPoint's published spec omits the (real, working)
# DELETE endpoint for this API - see the resource documentation's "Known
# Limitations & Live Testing Notes" for details.
resource "identitynow_access_model_metadata_attribute_v1" "example" {
  key         = "exampleDataClassification"
  name        = "Example Data Classification"
  description = "Classifies the sensitivity of data accessible via this object."
  multiselect = false

  # "all" applies to every access-item object type; alternatively scope to
  # specific types, e.g. ["entitlement", "role"].
  object_types = ["all"]

  values = [
    {
      value = "public"
      name  = "Public"
    },
    {
      value = "internal"
      name  = "Internal"
    },
    {
      value = "confidential"
      name  = "Confidential"
    },
  ]
}
```

## Known Limitations & Live Testing Notes

This resource is a `_v1` pilot: schema/model types are generated by
`tfplugingen-framework` from SailPoint's per-service `/access-model-metadata/v1`
OpenAPI spec, but Create/Read/Update/Delete are hand-written against the
`golang-sdk`'s `api_beta.AccessModelMetadataAPI` client.

-> **This is a distinct resource from the `access_model_metadata` block
embedded in `identitynow_role_v1` (and similarly on entitlement/access
profile resources upstream).** This resource manages the shared, tenant-wide
*taxonomy* itself (defining an attribute key, its display name, and its
allowed values) - the embedded block on other resources only *assigns*
existing taxonomy values to a specific role/entitlement/access profile. Define
your attributes and values here first, then reference their `key`/`value`
pairs from the consuming resource's `access_model_metadata` block.

~> **`Delete` uses a hand-rolled HTTP call, not the golang-sdk.**
`DELETE /access-model-metadata/attributes/{key}` is a real, working
IdentityNow/ISC endpoint (confirmed via a captured browser network call from
the Admin UI itself), but SailPoint's published OpenAPI spec for this service
omits it entirely, so `golang-sdk`'s generated `AccessModelMetadataAPIService`
has no delete method to call - this is a spec/SDK documentation gap, not a
real API limitation. This provider works around the gap with a small
hand-rolled HTTP DELETE call built from the SDK's own exported
configuration/auth fields (see
`resource_access_model_metadata_attribute_delete.go`); if SailPoint later
publishes this operation and a `golang-sdk` release generates a real method
for it, this provider should switch back to the generated call. A 404 during
delete is treated as already-deleted, not an error.

- **`key`, `type`, and `object_types` are immutable after creation.** The
  API accepts them at create time, but its own `PATCH` documentation lists
  only `name`, `description`, `multiselect`, and `values` as patchable. This
  provider applies `RequiresReplace()` to `key`/`type`/`object_types` so a
  config change to any of them forces a destroy+recreate rather than silently
  producing permanent, undetected drift.
- **`status` is effectively Computed-only.** There is no documented,
  practitioner-actionable way to set or change it, so it uses
  `UseStateForUnknown()` (like `id`/`created` on `role_v1`) rather than being
  treated as a writable field.
- **`name`, `description`, `multiselect`, and `values` are genuinely
  practitioner-writable** via the attribute-level `PATCH` - no
  `UseStateForUnknown()` is applied to these so that clearing a value back
  out (e.g. removing an entry from `values`) via config is honored rather
  than silently pinned to the prior state.
- **`values` is a nested list block** (not a raw JSON string like
  `transform_v1`'s `attributes`) - each entry's shape
  (`value`/`name`/`status`) is a simple, non-recursive DTO
  (`api_beta.AttributeValueDTO`), so it was safe to map directly via
  `associated_external_type` during codegen rather than needing the
  `jsontypes.Normalized` fallback pattern used for genuinely dynamic/
  discriminated-union fields elsewhere in this provider.
