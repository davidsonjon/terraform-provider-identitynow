# identitynow_entitlement_request_config_v1 (Resource)

Adopts and manages an existing entitlement's request/revocation approval configuration in IdentityNow/ISC by entitlement `id`. This target does **not** create or delete the underlying entitlement: Create and Update both call `PUT /entitlements/v1/{id}/entitlement-request-config`, while Delete removes only Terraform state.

## Example Usage

```terraform
# Adopt an already-existing entitlement by id first. Like
# identitynow_entitlement_v1 itself, this does not create or delete the
# upstream entitlement object.
resource "identitynow_entitlement_v1" "example" {
  id = "f45e991187dd4a9399d4f71954ec3029"
}

# Manage the adopted entitlement's request/revocation approval
# configuration. Destroy removes only Terraform state; it does not delete
# the entitlement or reset its upstream request configuration.
resource "identitynow_entitlement_request_config_v1" "example" {
  id = identitynow_entitlement_v1.example.id

  access_request_config = {
    approval_schemes = [
      {
        approver_type = "MANAGER"
      },
      {
        approver_type = "GOVERNANCE_GROUP"
        approver_id   = "00001078bd9c497a8122c6fc3f3571b1"
      },
    ]
    denial_comment_required  = true
    reauthorization_required = true
    request_comment_required = false
    require_end_date         = true
    max_permitted_access_duration = {
      value     = 30
      time_unit = "DAYS"
    }
  }

  revocation_request_config = {
    revocation_approval_schemes = [
      {
        approver_type = "WORKFLOW"
        approver_id   = "2c91808477d8f06d0177e1f4c9d000f9"
      },
    ]
  }
}
```

## Known Limitations & Live Testing Notes

This resource is a `_v1` pilot following the same **adopt-existing**
pattern as `identitynow_entitlement_v1`: schema/model types are generated
by `tfplugingen-framework` from SailPoint's per-service `/entitlements/v1`
OpenAPI spec, but Create/Read/Update/Delete are hand-written against the
`golang-sdk`'s `api_beta.EntitlementsAPI` client.

- **There is no standalone create/delete lifecycle for this object.**
  Entitlement request configuration is managed under an existing
  entitlement id. Create and Update both call
  `PUT /entitlements/v1/{id}/entitlement-request-config`; Delete only
  removes Terraform state and must not delete the underlying entitlement
  or attempt to reset its request configuration.
- **Unconfigured Optional+Computed fields are preserved from the live API
  object during PUT.** Because the generated schema exposes these nested
  blocks as Optional+Computed, the provider first reads the current live
  config, overlays the configured plan onto it, and only then performs the
  full-document replace. This avoids accidentally erasing omitted nested
  fields during adoption or update.
- **`revocation_approval_schemes` is a Terraform-only rename.** The real
  API field is still `revocationRequestConfig.approvalSchemes`, but this
  provider had to rename the Terraform attribute to
  `revocation_request_config.revocation_approval_schemes` to avoid a
  duplicate generated Go type name collision with
  `access_request_config.approval_schemes`.
